# Choose a hands-on learning route

[Table of contents](../CONTENTS.md)

Choose one small outcome for a session. You do not need to complete every resource, install a game, or publish every practice attempt.

## Route A: I need to see Git move

Use the free browser resource in [lab 11](../labs/11-visual-git-challenge.md). Predict one operation and watch its graph change. Next, complete the local exercise in [lab 12](../labs/12-read-a-local-history.md). Explain which parts the simulator simplified, such as editing and staging files.

Finish with challenge 1 or 2 in the [troubleshooting workbook](troubleshooting-challenges.md).

## Route B: I want a guided GitHub task

Choose one official interactive course from the [resource guide](../docs/visual-learning-resources.md). Use its own current instructions and your own practice repository. Afterward, identify the file change, commit, branch, and PR involved. If a step did not work, use the [first steps guide](../docs/troubleshooting-first-steps.md) to describe the error before trying unrelated fixes.

Finish by explaining one result without reading the course's answer.

## Route C: I already enjoy a data-center game

Use an observation from your game as the subject of [lab 13](../labs/13-observation-to-pull-request.md). Track a documentation task, propose a note, and review it. Separate what the game displayed from what you infer about real equipment.

The [resource guide](../docs/visual-learning-resources.md) identifies optional paid titles and their limits. No game purchase is needed: a Git simulation observation works for the same lab.

## Route D: I want to investigate a failure

Use the deliberate test failure in [lab 2](../labs/02-environments-and-actions.md) in your fork. Read the failed assertion, explain the difference between expected and actual behavior, restore the intended mapping, and check the corrected run.

Finish with a brief record of what failed and what evidence supports the fix. Do not merge the intentionally broken version into your main branch.

## Keep a useful stopping point

A session is complete when you can explain the result and identify the evidence. If you cannot, record the unanswered question in the [review log](review-log.md). Continue from that question next time instead of restarting an entire course.

For broader practice, use the [seven chapter missions](visual-missions.md). None of these completion rules is an exam score or an official credential.
