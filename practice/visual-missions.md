# Seven visual and hands-on missions

[Table of contents](../CONTENTS.md) · [Resource guide](../docs/visual-learning-resources.md)

Pick one mission per session. Each has an observable finish condition. These are original practice activities, not exam questions, official badges, or a promise of readiness.

| Chapter | Mission | Finish when you can show |
| --- | --- | --- |
| Git basics | Complete [lab 11](../labs/11-visual-git-challenge.md), then compare with [lab 12](../labs/12-read-a-local-history.md) | A graph and an explanation of one branch operation |
| Repositories | Sketch a repository's supporting files and the question each answers | Correct paths to README, contribution guidance, and security reporting guidance, or an accurate note that one is absent |
| Collaboration | Complete [lab 13](../labs/13-observation-to-pull-request.md) | A focused PR and a description of the reviewed change |
| Modern development | Inspect a run of this repo's checks workflow | The event, job, failed or successful step, and commit it tested |
| Projects | Display the same practice items in a board and table | An explanation of how the views differ without duplicating issues |
| Security | Compare two fictional access requests using [lab 4](../labs/04-team-management.md) | The smallest appropriate role for each request and why a broader role is unnecessary |
| Community | Review a project's contribution instructions and draft a small improvement in your notes | The problem, proposed change, and how you would verify it; sending it is optional |

## Add a challenge without chasing a score

Before acting, predict the result. After acting, explain what changed. Finally, change one condition and describe the new decision. For example, change “inspect a repository” to “push a documentation branch” and revisit the access needed.

If a mission fails, record the observed error and what you tried. An accurately explained failure can teach more than repeatedly clicking through a familiar success. Do not mark a simulated task as real workplace experience.

## Choose your next mission

Use the [review log](review-log.md) to record the gap and the next small task. If you cannot name the feature, return to the chapter. If you can name it but cannot demonstrate it, use the linked lab.
