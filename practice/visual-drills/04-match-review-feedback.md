# Match feedback to a repair

[Visual drill menu](README.md)

This is an original fictional exercise. The table is supplied practice material, not a record of a real game session.

| Review comment | Proposed repair |
| --- | --- |
| I cannot repeat your steps. | Add starting conditions and ordered actions. |
| This conclusion goes beyond the test. | Narrow the claim and state what remains unknown. |
| This link does not reach the lab. | Correct the destination and follow it to check. |

## Try it first

Cover the repair column. Propose a specific revision for each comment, then compare it with the example.

<details>
<summary>Worked explanation</summary>

Each repair addresses a different problem: reproducibility, reasoning, or navigation. Rewording the conclusion cannot repair a broken link. Adding screenshots does not necessarily supply missing steps.

</details>

## Apply it in GitHub

Choose one of your sandbox notes and review it for these three problems. Make only corrections supported by the note. If none apply, record what you inspected instead of inventing a defect.

Finish when you can explain your choice and point to the evidence that supports it. Use [the existing labs](../../CONTENTS.md#labs-in-order) for setup instructions.
