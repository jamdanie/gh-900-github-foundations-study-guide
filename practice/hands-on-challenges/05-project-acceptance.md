# Challenge 5: Give a board card a finish condition

[Challenge menu](README.md) · [Project setup lab](../../labs/03-project-board.md)

A fictional board card says “Learn GitHub.” You cannot tell what work it includes or when it is done.

## Make it actionable

In your own sandbox, create an issue called “Document one simulator observation.” Put this scope in its description:

- Record the starting state, one action, and the displayed result.
- Include a limitation explaining what the observation doesn't prove.
- Link the reviewed documentation change.
- Verify that the note can be reached from the sandbox README.

Add the issue to a Project using the linked setup lab. Move it to In progress when you begin the task. Link your documentation PR in the issue.

## Decide whether it is done

Suppose the note exists and its links work, but it claims that one successful simulated repair proves the whole network is secure. Should the card move to Done?

<details>
<summary>Worked answer</summary>

No. The limitation requirement is unmet. Revise the claim and inspect the updated note before marking the work complete. A file existing is only one part of the finish condition.

</details>

## Separate completion from understanding

After completing the issue, explain why you used an issue, a branch, a PR, and a Project. If you cannot explain a step, record that as a study question. Completing the documentation task doesn't automatically answer it.

Finish when the card points to evidence for every requirement. If you work alone, record your self-review honestly.
