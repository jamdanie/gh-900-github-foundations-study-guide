# Challenge 8: Check progress with evidence

[Challenge menu](README.md)

Choose one completed challenge. Give yourself one point for each statement you can support:

| Check | Evidence to show |
| --- | --- |
| I predicted an outcome | A prediction written before the action |
| I observed a result | A specific output, file version, or recorded state |
| I explained the result | A reason connected to the action |
| I can handle a changed requirement | A second scenario and justified next step |

This four-point rubric is a study aid created for this guide, not an exam score or pass prediction. A low result tells you which step to repeat.

## Check published activity separately

A file count is not a contribution count. Several files can belong to one commit, and one push can publish multiple commits.

GitHub's contribution rules require commit attribution to an associated email, an eligible branch, and a standalone repository, along with a qualifying relationship to the repository. Inspect the actual commit page and branch before assuming activity will appear. A fork used for practice can behave differently from a standalone repository on your profile.

GitHub says qualifying contributions may take up to 24 hours to appear. This guide does not promise a particular calendar shade or a fixed number that produces it.

## Choose the next useful update

If the explanation was weak, improve the explanation. If the links were broken, repair and check them. If a task was too large, split it into understandable work. Each change should leave something a reader can use.
