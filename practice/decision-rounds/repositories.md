## 1. A repository identifies owners for documentation paths, but their approval is not required to merge. What is missing from that description?

A. A larger README

B. A rule requiring the relevant review

C. A second fork

D. More stars

<details>
<summary>Answer and explanations</summary>

Correct answer: **B**.

- A. README length does not enforce a merge condition.
- B. Ownership identification and enforcing approval are different; inspect the applicable review rule.
- C. Creating a fork does not enforce a review in the source repository.
- D. Stars do not enforce access or merge rules.

</details>

## 2. A new contributor wants to learn the project's preferred process for proposing a correction. Which file is the best starting point?

A. CONTRIBUTING

B. LICENSE

C. The largest source file

D. A random workflow log

<details>
<summary>Answer and explanations</summary>

Correct answer: **A**.

- A. Contribution guidance explains how the project expects proposed changes.
- B. A license describes reuse terms, not necessarily the contribution process.
- C. File size does not identify contribution instructions.
- D. A log reports an execution result, not the general contribution process.

</details>

## Hands-on challenge

Find the contribution instructions in a repository you use. Record one requested check before proposing an edit. If the file is absent, say so instead of inventing guidance.
