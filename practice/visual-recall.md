# Visual practice recall cards

[Table of contents](../CONTENTS.md)

Ten original short-answer cards supplement the existing multiple-choice deck. They are not included in the CLI quiz or its 35-question count.

## 1. What separates a branch from a tag?

<details>
<summary>Answer and reason</summary>

A branch supports an ongoing line of work; a tag names a particular point in history. Use the purpose of the reference to decide which fits.

</details>

## 2. Does publishing a release create a Pages website?

<details>
<summary>Answer and reason</summary>

No. A release packages a version with notes and assets. Pages publishes static website content. They address different reader tasks.

</details>

## 3. What should accompany a learning diagram?

<details>
<summary>Answer and reason</summary>

A text explanation of the same relationship, meaningful labels, and a check that arrow directions agree with the explanation.

</details>

## 4. What can one simulated link-failure observation establish?

<details>
<summary>Answer and reason</summary>

It supports a statement about that tested condition. It does not prove the behavior of every other path or a real production system.

</details>

## 5. Where should a project reader look first for an overview?

<details>
<summary>Answer and reason</summary>

The README is a usual starting point for purpose, setup, and navigation. Detailed supporting material can live in linked documentation.

</details>

## 6. Why might a release differ from the latest branch content?

<details>
<summary>Answer and reason</summary>

A release is based on a particular tag, while the branch may have received additional commits afterward.

</details>

## 7. Does a diagram rendering successfully prove its conclusion?

<details>
<summary>Answer and reason</summary>

No. Rendering shows that the syntax can be displayed. The drawing and its claims still need to agree with the evidence.

</details>

## 8. What is a useful finish condition for the simulation note?

<details>
<summary>Answer and reason</summary>

The note and diagram identify the observed condition, action, result, and untested conditions without claiming production experience.

</details>

## 9. What is the difference between merging a report and fixing a service?

<details>
<summary>Answer and reason</summary>

Merging integrates the report's file changes. It does not itself perform or validate an infrastructure repair.

</details>

## 10. What should be recorded if no automated check ran?

<details>
<summary>Answer and reason</summary>

State that no automated check ran and name the manual checks actually performed. Do not substitute an assumed passing result.

</details>
