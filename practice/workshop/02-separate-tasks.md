# Split a task without losing its purpose

[Workshop menu](README.md)

## Situation

A fictional issue asks for a topology diagram, a glossary, a caption, and a reviewed explanation of a failed simulation.

## Decide first

Choose parts that could be reviewed independently and identify their dependency.

<details>
<summary>Worked explanation</summary>

The glossary can be reviewed independently. The caption depends on the finished diagram. Keep the parent issue's overall goal visible so completing one part does not imply all work is complete.

</details>

## Try it

Write a parent issue description in your sandbox, then describe two smaller tasks with separate finish conditions. You can do the exercise on paper without creating issues.

Finish check: Each smaller task produces a useful result; the parent goal remains clear.

## Change the situation

If the diagram changes, which completed work needs another check? Recheck its caption and any explanation that refers to it.

These are original practice situations, not recalled exam questions or claims about the author's experience.
