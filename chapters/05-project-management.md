# Chapter 5: Projects and planning

[Table of contents](../CONTENTS.md) · [Previous chapter](04-modern-development.md) · [Next chapter](06-security-administration.md)

Use planning tools to answer specific questions: what needs doing, who is responsible, what status it has, and when it is planned. A chart or board is only useful when you understand the data behind it.

## Key terms

| Term | Meaning |
| --- | --- |
| Project | Organizes and tracks work items. |
| Board | A view that groups items into columns. |
| Milestone | Groups repository work toward a target. |
| Iteration | A field for repeating work periods. |

## Worked example

You track three study issues in one Project. A board groups them by status; a table helps compare fields; a roadmap shows scheduling information. You do not need three separate copies of each issue just because you want three views.

## Where people get confused

Project status and issue state are distinct. Check configured automation before assuming Done closes an issue. A completion percentage describes the tracked items, not your exam mastery. You still need to explain and apply the concepts.
