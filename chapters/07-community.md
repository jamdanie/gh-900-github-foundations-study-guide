# Chapter 7: Community and contributions

[Table of contents](../CONTENTS.md) · [Previous chapter](06-security-administration.md)

A useful contribution helps the project and can be small. Clear documentation, a reproducible problem report, or a focused test can give a maintainer something concrete to review.

## Key terms

| Term | Meaning |
| --- | --- |
| Open source | Software made available under a license permitting specified use, modification, and sharing. |
| InnerSource | Open-source collaboration practices used inside an organization. |
| Marketplace | A place to discover GitHub integrations and actions. |
| Sponsors | A way to financially support eligible open-source contributors. |

## Worked example

You understand a documentation problem in a project you use. Read its contribution instructions, check whether the problem is already tracked, and propose a focused correction. Describe the change and how you checked it so the maintainer can review your work.

## Where people get confused

Starring, watching, and sponsoring have different purposes. Saving a repository does not send financial support. Finding an integration in Marketplace also does not replace reading its permissions, documentation, and terms before installation.

## Learn from a project's contribution route

Explore an open-source learning tool listed in the [visual resource guide](../docs/visual-learning-resources.md). Read its contribution guidance and identify one question you would need answered before proposing a change. Write the proposal in your own notes first. Describe a submitted contribution only if you actually submit one; a game completion is not a contribution to its source repository.

## Practice and review

Describe a documentation contribution you could make without claiming you already completed it. Explain how you would keep the change focused and verify the result.

From the repository root, use `python scripts/quiz.py --domain community` for the existing five-question domain sample. The sample is not a readiness prediction. Record what you could explain and what still needs practice in the [review log](../practice/review-log.md).
