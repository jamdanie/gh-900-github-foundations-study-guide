# Tags and release notes

[Table of contents](../CONTENTS.md)

This is supporting repository practice. It is not a new weighted GH-900 exam domain.

A tag names a particular point in Git history. A GitHub release is based on a tag and can include release notes and downloadable files. A branch supports ongoing work; a tag is useful when referring to a specific version.

## Describe the change for the reader

Useful release notes explain what changed, who needs it, and any known limits. For a study guide, “Added diagram practice and corrected a broken resource link” is more informative than “Lots of updates.”

Do not claim the guide covers every exam question or guarantees a pass. Describe the actual content added and checked.

## Inspect before creating

Choose a repository with a release and compare its tag, notes, and downloadable assets. If none exists in your practice repository, write a draft note locally instead. There is no need to publish a release just to finish this reading exercise.

Explain what a reader would receive from the release and whether that differs from the latest branch content. A release date and a tag date can differ.

Source: [About releases](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases). Compare [publishing features](choose-a-publishing-feature.md).
